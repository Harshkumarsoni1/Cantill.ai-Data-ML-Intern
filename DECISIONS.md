# Data decisions

- The build preserves the sign of credits, rounds net spend to two decimal places at export, and keeps one output row per source ID. A negative amount alone does not justify dropping a transaction.
- A's ERP receipts are primary and net. Tool VAT appears as a fraction, percent string, whole percent or blank. Blank means 15%; explicit zero means zero. Invalid or missing dates produce a local audit flag and do not invalidate an otherwise supported purchase. A had 43,030 blank or unparseable dates.
- Explicit cancellation or unapproved status takes precedence over duplication. Of A's tool rows, 188 were cancelled and 315 otherwise unapproved. A repeated invoice number can refer to multiple lines. We use invoice, supplier, normalized description, quantity and amount together for repeated exports. Identical real lines can still collide. Cross-system candidates with missing PO need close amounts and similar descriptions. We marked 21,897 rows duplicate. No ground truth for these links was provided.
- In B, ERP posting is the available evidence of approval because there is no explicit invoice-status column. Treat intercompany accounts and explicit tax, revenue, royalty, partner-billing and financing language as non-procurement. Keep generic payable accounts eligible. Repeated, unanimously labelled descriptions supplement the text rules. No change of spend sign or exclusion is inferred from an unfamiliar document code.
- USD amounts pass through. Convert other currencies by dividing by the positive line rate or the matching monthly FX rate. If the invoice date cannot be parsed, try the configured posting date. Three B inputs lack amounts and five lack usable FX. Unknown spend is represented as zero with a private diagnostic flag; totals may understate spend. The audit lists record IDs and flags separately from the required output schema.
- Prefer a material code or a uniquely supported description-to-code mapping. For uncoded items use normalized description; for missing descriptions and codes keep separate row identities. Generic descriptions can over-group unrelated purchases. The legal-suffix normalization can also merge unrelated suppliers. B provides vendor IDs only, so cross-ERP supplier aliases are unresolved.
- A zero-overlap classification tie uses the first path in file order with zero confidence when supplier context is unavailable. In low-information cases treat predictions as uncertain. Excluded rows have blank category fields and zero confidence.
